# 役割：フロントエンドとゲームロジックの境界線

GameSession はゲームの唯一のエントリーポイント。CLI・React・FastAPI など、どのフロントエンドからでもこの1クラスを呼ぶだけでゲームが動く。LLM呼び出し・KG参照・バリデーションはすべて内部に隠蔽されており、外側には構造化データだけが返ってくる。

フロントエンドが自由に管理してよい状態（メモ・気になるリスト・UI表示など）は GameSession に持ち込まない。バックエンドが管理するのは以下の5つだけ：

操作メソッド説明
尋問ask()LLMに質問し、検証済み回答を返す
容疑者切替switch_suspect()現在の尋問対象を変更する
場所の調査examine_location()場所を調べ、アイテムを発見する
アイテム詳細examine_item()発見済みアイテムの詳細を返す
起訴indict()犯人を指名し、正誤を判定する

# 初期化：何が「一度だけ」作られるか

session = GameSession("scenarios/the_final_act.json", language="ja")

__init__ の中でゲームに必要なすべての重いオブジェクトが一度だけ構築される。各容疑者の サブグラフ（KGの部分グラフ）はここで1回だけビルドされ、その後は変わらない。

オブジェクト型変化するか
loaderScenarioLoader変化しない（シナリオJSONの読み取り専用）
ledgerCommitmentLedger毎ターン蓄積（容疑者の発言履歴）
trackerLocationTrackerexamine のたびに更新
agentsdict[str, SuspectAgentKG]変化しない（サブグラフは初期化時に確定）
current_suspect_idstr | Noneswitch_suspect() のたびに変わる
turnintask() のたびにインクリメント

つまり 「何を知っているか（サブグラフ）」は固定 で、「何を話したか（ledger）」だけが蓄積 されていく。毎ターン build_system_prompt() が呼ばれるとき、固定サブグラフ＋最新のledgerテキストが組み合わさって容疑者のシステムプロンプトが生成される。

日本語モードでは、KGやシナリオJSONに英語で保存された説明文を表示直前に translate_display_text() で日本語化する。翻訳結果は GameSession 内でキャッシュされるため、同じ説明文を表示するたびにLLMを呼ぶわけではない。人物名・場所名・アイテム名は display_names_ja を優先して使う。

# ask() の内部フロー（9ステップ）

01
言語チェック

lang == "ja" なら質問文を translate_question_to_english() で英語化

02
ledger_text 取得

この容疑者のこれまでの発言要約を CommitmentLedger から取得

03
システムプロンプト構築

build_system_prompt(subgraph, nodes, ledger_text) — サブグラフの公開トリプル・隠蔽エッジ・ledger を結合

04
LLM 呼び出し（最大3回）

llm_messages([system, user]) → JSON文字列を受け取る

05
バリデーション

validate_response() がJSONフォーマット・隠蔽エッジ漏洩・ledger矛盾を検査

06
失敗 → ヒント付きリトライ

バリデーション失敗時、エラー内容を user メッセージに付加して再送（最大3回）

07
ledger 更新

検証済みの発言・使用エッジIDを CommitmentLedger に記録

08
場所アンロック

tracker.unlock_from_testimony(used_edge_ids) — 証言に含まれた場所を調査可能にする

09
翻訳して返す

lang == "ja" なら translate_response() で日本語化してから返す

# get_briefing()

get_briefing() → dict

ゲーム開始時に一度呼ぶ。タイトル・設定・被害者情報・事件発生時刻・事件発覚時刻・容疑者リストを返す。被害者情報は murder_details.public_summary を優先し、犯人の侵入経路など調査で明らかにすべき真相は出さない。日本語モードでは表示文を翻訳して返す。

Returns
{"title": str, "setting": str, "victim": str, "time_of_murder": str, "time_discovered": str, "weapon": str, "scene": str, "suspects": list[SuspectInfo]}
# 使用例
briefing = session.get_briefing()
print(briefing["title"])     # ja mode: 翻訳済みタイトル
print(briefing["time_of_murder"])     # ja mode: "午後9時5分ごろ"
print(briefing["time_discovered"])    # ja mode: "午後9時20分"
print(briefing["weapon"])    # ja mode: 翻訳済み凶器説明
for s in briefing["suspects"]:
    print(s.id, s.name)

# switch_suspect()

switch_suspect(suspect_id: str) → SuspectInfo

尋問対象を切り替える。この呼び出し以降の ask() は指定した容疑者に送られる。LLM呼び出しなし。

Raises
ValueError — 存在しないsuspect_idを渡した場合

# ask()

ask(text: str) → str

現在の容疑者にテキストで質問し、完全な回答文字列を返す。内部でLLM呼び出し・バリデーション・翻訳が行われる。switch_suspect() を事前に呼んでいない場合は RuntimeError。

Input
text — プレイヤーの質問（日本語モードなら日本語のまま渡してよい）
Returns
容疑者の回答文字列（日本語モードなら日本語）

# get_examine_options()

get_examine_options() → dict

現在調査できる場所と、発見済みアイテムの一覧を返す。UIの調査メニューを描画するために呼ぶ。日本語モードではアイテム説明を翻訳して返す。

Returns
{"locations": list[LocationInfo], "items": list[ItemInfo]}

# examine_location()

examine_location(location_id: str) → ExamineResult

指定した場所を調査する。新しいアイテムが見つかれば newly_found に入る。同じ場所を再度調べた場合は already_found に移る。日本語モードでは場所説明とアイテム説明を翻訳して返す。

# examine_item()

examine_item(item_id: str) → ItemDetail

発見済みアイテムの詳細を返す。unlocked_location が非 None の場合、そのアイテムを調べたことで新しい場所が解放されたことを意味する。日本語モードでは説明とsignificanceを翻訳して返す。

# indict()

indict(suspect_id: str, reason: str) → IndictResult

犯人を理由付きで指名する。理由文はLLMでKG edgeにマッピングされ、勝敗は solution.proof_graph の必須グループ・重み付きスコアでルールベース判定される。

result = session.indict(
    "n_elena",
    "The compact was in the vent shaft and it belonged to Elena."
)
if result.won:
    show_ending(result.message)
else:
    show_wrong(result.accused_name, result.message, result.evaluation)

# get_state()

get_state() → GameState

ゲームの現在の全状態を返す。ask() の直後に呼ぶことで、証言によって新しくアンロックされた場所（is_new=True）を検出できる。日本語モードでは表示名・説明が日本語化される。

# ask() 直後に新しい場所を確認
response = session.ask(user_input)
state = session.get_state()
for loc in state.available_locations:
    if loc.is_new:
        notify(f"新しい場所が解放されました: {loc.name}")

# CLI vs React：フロントエンドごとの違い

どちらのフロントエンドも GameSession の同じメソッドを呼ぶ。違いはデータの受け取り方と表示だけ。

CLI（run_game_kg.py）

  • get_briefing() → print で表示
  • switch_suspect() → 番号入力で選択
  • ask() → print で表示
  • examine_location() → print で表示
  • get_state() → 新場所を print
  • indict() → print して sys.exit(0)

React（FastAPI 経由）

  • get_briefing() → JSON レスポンス
  • switch_suspect() → POST /suspect/{id}
  • ask() → POST /ask → SSE ストリーム
  • examine_location() → POST /examine
  • get_state() → GET /state
  • indict() → POST /indict

フロントエンドが自由に管理してよいもの

以下はバックエンドに影響せず、フロントエンドだけで完結できる：

機能説明
気になるリスト 発見アイテムや発言をローカルで bookmark するだけ。GameSession は関係ない。
探偵メモ プレイヤーが自由に書くメモ。バックエンド状態に影響しない。
容疑者の移動アニメーション switch_suspect() の戻り値（名前）を使ってUIを演出するだけ。
場所移動の演出 examine_location() 成功後にアニメーションを入れるのはフロント側の自由。
会話履歴の表示 ask() の呼び出し結果をフロントでリストに積む。GameSession は最新の ledger を内部管理している。
