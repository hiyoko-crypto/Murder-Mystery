2. LLMへの入力（System Prompt 構成）

① キャラクター定義（ノードプロパティから）

knowledge_graph.nodes の properties を使用。

あなたは Elena Rostova です。
Bio: 34歳、主役女優。借金を盾に2年間支配されてきた...
Tags: [composed, calculating, deflects with charm, precise under pressure]
Interrogation style: 落ち着いて話す。Julian の手紙や Leo の解雇に話題を誘導する。
② サブグラフ — 使用可能なトリプル（visible_edges）

エッジIDと properties 付きのトリプル形式で渡す。LLMはこれを根拠にのみ発話する。

【あなたが知っている事実】
e10: Elena --[HAS_MOTIVE]--> Marcus       "借金契約による2年間の支配"
e13: Elena --[VISITED]--> Dressing_Room   @ 7:00PM  "ブロッキングの相談と称して"
e15: Elena --[PERFORMED_ON]--> Stage      @ 7:15PM-9:00PM
e19: Elena --[WAS_IN]--> Elena_Room       @ 9:10PM  "アリバイ主張"
e22: Torn_Letter --[WRITTEN_BY]--> Julian
e23: Julian --[SAW]--> Elena              @ 7:05PM  "廊下ですれ違った"
e25: Leo --[FIRED_BY]--> Marcus           @ 10:00AM
...
③ 発話禁止トリプル（hidden_edges）

渡すが発話禁止指示付き。知っているからこそ犯人らしい緊張・回避が生まれる。渡さないと演技ができない。

【知っているが絶対に言ってはいけない事実】
e14: Elena --[POISONED]--> Cyanide_Wine   @ 7:00PM
e16: Elena --[CRAWLED_THROUGH]--> Vent_Shaft  @ 9:00PM
e17: Elena --[DROPPED]--> Silver_Compact  @ 9:05PM

→ これらの話題に近づかれたら話をそらすか否定すること。
   動揺を内に秘めつつ表面上は冷静に振る舞うこと。
④ Commitment Ledger（過去の発言）

入力として渡すことで一貫性を保つ。バリデーターの安全網と二重で使用する。

【これまで探偵に述べたこと — 矛盾してはいけない】
Turn 1: e19 を使用 → "9:10PM は自分の楽屋にいた"
Turn 2: e15 を使用 → "Act1中はステージで演じていた"
Turn 3: e13 を使用 → "7:00PMに楽屋を訪問したと認めた"

3. LLMの出力形式（構造化JSON）

出力スキーマ
{
  "response":         "発話内容（プレイヤーに見せるテキスト）",
  "used_edge_ids":    ["e19", "e10"],
  "asserted_triples": [
    ["Elena", "WAS_IN", "Elena_Room"]
  ]
}

後処理でのトリプル抽出は7Bモデルで不安定なため、LLMに直接出力させる。

4. Validator（出力後チェック）

チェック項目方法失敗時
hidden_edges の漏洩 used_edge_ids に hidden_edges が含まれていないか 再生成（最大3回）
Ledger との矛盾 asserted_triples が過去の発言と同ノード・同時刻で矛盾しないか 矛盾を明示して再生成
JSON 形式エラー 出力が有効な JSON かどうか 再生成

5. Commitment Ledger の管理

KGとして管理（ランタイムはDict、シリアライズ可能）
{
  "n_elena": [
    {
      "turn":             1,
      "question":         "Where were you at 9PM?",
      "used_edge_ids":    ["e19"],
      "asserted_triples": [["Elena", "WAS_IN", "Elena_Room"]],
      "response_summary": "9:10PMは楽屋にいたと主張"
    }
  ]
}

矛盾検出：新しい asserted_triples が同一ノード・同一時刻で異なる述語を持つ場合に検出。

7. 設計上の決定事項

論点決定理由
サブグラフの渡し方 プロパティ付きトリプル（エッジID付き） 純粋JSONより推論しやすく、used_edge_ids と照合可能
hidden_edges の扱い 渡すが発話禁止指示付き 渡さないと犯人が緊張・回避の演技ができない
トリプル抽出 LLMに直接出力させる 後処理抽出は7Bモデルで不安定
Commitment Ledger の用途 LLM入力 ＋ Validator の両方 入力なしだと矛盾が繰り返し発生する
Ledger の形式 KG互換のDict（エッジID参照） グラフDB移行時にそのままマッピング可能
ChromaDB / RAG 廃止 サブグラフで代替。7Bモデルのコンテキストに収まる
