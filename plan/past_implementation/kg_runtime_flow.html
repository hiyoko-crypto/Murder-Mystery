2. 起動時の構築

build_and_run_game() でシナリオを読み込み、共有の CommitmentLedger と LocationTracker を作成する。その後、容疑者ごとに SuspectAgentKG を生成する。 

loader  = ScenarioLoader(scenario_path)
ledger  = CommitmentLedger()
tracker = LocationTracker(loader)

agents = [
    SuspectAgentKG(loader, node_id, ledger)
    for node_id in loader.get_all_suspect_node_ids()
]
要素役割保存場所
ScenarioLoader JSONを読み込み、nodes、edges、suspects をID辞書化する。 modules/scenario_loader.py
CommitmentLedger 容疑者ごとの過去発言、使用edge、asserted triplesをメモリ上に保存する。 suspect_agents/commitment_ledger.py
SuspectAgentKG 容疑者ごとのサブグラフを保持し、尋問時にLLMを呼ぶ。 suspect_agents/suspect_agent_kg.py

3. サブグラフ抽出

現在のサブグラフ抽出は動的なグラフ探索ではない。scenarios/the_final_act.json の suspects[].subgraph.visible_edges と hidden_edges に書かれたedge IDを、 ScenarioLoader.get_subgraph() が実体のedge dictへ変換する。 

{
  "node":            self.nodes[node_id],
  "visible_edges":   [self.edges[eid], ...],
  "hidden_edges":    [self.edges[eid], ...],
  "hidden_edge_ids": set([...]),
  "timeline":        []
}
分類LLMへの渡し方意味
visible_edges [Facts you know] に入る。 容疑者が話してよい事実。公開情報や本人が知っていても漏らしてよい情報。
hidden_edges [Facts you know but must NOT reveal] に入る。 容疑者は知っているが、探偵に明かしてはいけない真相。
hidden_edge_ids LLMには直接の禁止リストとして入るほか、validatorにも渡る。 回答JSONの used_edge_ids に含まれたら漏洩として拒否する。
旧 timeline の重要情報はKG edgeへ統合済み。現在の尋問プロンプトは、KG edgeを情報源として使う。

4. LLM入力

尋問時、LLMへ渡すmessageは system と user の2つ。systemには容疑者設定とサブグラフ、 userにはプレイヤーの質問を入れる。日本語モードでは、先に質問を英語へ正規化する。 

question_for_llm = user_message
if get_lang() == "ja":
    question_for_llm = translate_question_to_english(user_message)

messages = [
    {"role": "system", "content": system_content},
    {"role": "user", "content": f"Detective: {question_for_llm}"}
]

system prompt の中身

ブロック内容
Character identity name、bio、tags、interrogation_style。
Facts you know visible edgeを拡張tripleとして列挙する。
Facts you know but must NOT reveal hidden edgeを拡張tripleとして列挙し、漏らさないよう指示する。
Commitment ledger 2ターン目以降、直近最大6ターンの発言要約を入れる。
Output format response、used_edge_ids、asserted_triples を持つJSONのみを要求する。

edgeの渡し方

edgeは純粋な3要素だけではなく、edge ID、時刻、detailを付けた拡張tripleとして渡す。

e13: Elena Rostova --[VISITED]--> Marcus's Dressing Room  @ 7:00 PM  "Claimed to discuss blocking notes; secretly loosened the vent grate with a small screwdriver"

LLMに要求する出力

{
  "response": "Your spoken response in English",
  "used_edge_ids": ["e1", "e2"],
  "asserted_triples": [["Subject", "REL", "Object"]]
}

5. Validator

LLMの生出力はそのまま表示せず、validate_response() を通す。 失敗した場合は最大3回まで、エラー内容を添えて再生成を求める。

Raw LLM Output文字列
→
JSON parse抽出とparse
→
Fields必須確認
→
Hidden leakedge ID確認
→
Ledger矛盾確認
検証条件失敗例
JSON parse 出力からJSONオブジェクトを抽出してparseできること。 自然文だけ、壊れたJSON。
必須フィールド response が文字列として存在すること。 {"answer": "..."}
hidden edge漏洩 used_edge_ids に hidden_edge_ids が含まれないこと。 Elenaが e14、e16、e17、e28 を使用edgeとして申告する。
ledger矛盾 新しい asserted_triples が過去発言のtripleと衝突しないこと。 以前と同じsubject + relationで、objectだけ違う。
現在のhidden漏洩チェックは used_edge_ids ベース。回答本文が秘匿事実を漏らしているのにedge IDを申告しなかった場合、意味レベルでは検出できない。

6. Ledger

Ledgerはメモリ上に保存される。1つの CommitmentLedger を全エージェントで共有するが、 中身は node_id ごとに分かれる。 

{
  "n_elena": [
    {
      "turn": 1,
      "question": "...",
      "used_edge_ids": ["e19"],
      "asserted_triples": [
        ["Elena Rostova", "WAS_IN", "Elena's Dressing Room"]
      ],
      "response_summary": "I was in my dressing room..."
    }
  ]
}

保存タイミング

LLM出力がvalidatorを通過した後、add_turn() で保存する。 保存されるのは、質問、使用edge、asserted triples、応答の短い要約。

LLMへの渡し方

get_ledger_text(node_id, max_turns=6) が直近最大6ターンを短いテキストに変換し、 system promptの [What you have told the detective so far - maintain consistency] に挿入する。 

Turn 1 (edges: e19): I was in my dressing room...
Turn 2 (edges: e13): I went to Marcus's room earlier...

矛盾チェック

新しい asserted_triples と過去の asserted_triples を比較する。 現在の条件は subject と relation が同じで、object が違う場合のみ矛盾。 

past: ["Elena Rostova", "WAS_IN", "Elena's Dressing Room"]
new:  ["Elena Rostova", "WAS_IN", "Theatre Lobby"]

=> contradiction
現在の矛盾チェックは時刻や否定を見ない。将来的には time と polarity を持つ構造化claimへ拡張するとよい。

7. 日本語モード

日本語モードでは、プレイヤーの質問をまず translate_question_to_english() で英語へ正規化する。 その英語質問をKGプロンプトへ渡し、一次回答も英語JSONで生成する。validatorを通過してledgerへ保存した後、 表示直前に translate_response() で日本語へ変換する。

Japanese question入力
→
English question質問正規化
→
English promptKG推論
→
English JSONresponse取得
→
Validator事実検証
→
Ledger英語で保存
→
Japanese表示翻訳

質問翻訳と応答翻訳の両方で、事実の追加、削除、推測、変更を禁止している。 固有名詞は display_names_ja の対応表を使う。

8. Location Tracker

LocationTracker は、プレイヤーの探索進行をメモリ上で管理する。 追跡しているのは、調査可能な場所、調査済みの場所、発見済みアイテムの3種類。 

self.known_locations     # プレイヤーが調査可能な場所
self.examined_locations  # すでに調べた場所
self.found_items         # 発見済みアイテム

初期状態

examine_rules.locations のうち、initially_available: true の場所だけが known_locations に入る。現在は n_dressing_room、つまりマーカスの楽屋から始まる。

Known location楽屋
→
Examine location証拠品発見
→
Examine item場所解放
→
Testimony証言で場所解放

場所を調べる

examine_location(location_id) は、場所を examined_locations に追加し、 その場所の items_present を found_items に追加する。 楽屋を調べると、燭台、破れた手紙、換気口、鍵のかかった扉が見つかる。

アイテムを調べる

examine_item(item_id) は、examine_rules.items[item_id].unlocks_location を見る。 現在は n_vent_grate を調べると n_vent_shaft が解放される。 

"n_vent_grate": {
  "unlocks_location": "n_vent_shaft"
}

証言から場所を解放する

容疑者の回答後、active_agent.last_used_edge_ids を unlock_from_testimony() に渡す。各edgeの from / to に場所ノードが含まれ、 その場所の unlock_from_testimony が true なら、新しい調査場所として解放される。 

response = current_fn(user_input)
newly = tracker.unlock_from_testimony(active_agent.last_used_edge_ids)
場所解放条件例
n_dressing_room 最初から解放済み。 事件現場として最初に調査できる。
n_vent_shaft アイテム n_vent_grate を調べる。 換気口を調べると換気ダクトが調査可能になる。
n_lobby 証言edgeに含まれる。 Julianの e24 が使われるとロビーが解放される。
n_bar 証言edgeに含まれる。 Leoの e26 が使われるとバーが解放される。
n_elena_room 証言edgeに含まれる。 Elenaの楽屋に関係するedgeが使われると解放される。
現在の証言ベース解放は used_edge_ids に依存する。回答本文で場所に触れていても、LLMが対応edge IDを申告しなければ場所は解放されない。

9. 現在の制約と次の改善候補

項目現在改善候補
サブグラフ抽出 JSONの明示edge IDリスト。 visible_to から自動生成する仕組みを追加すると、シナリオ作成時の重複を減らせる。
hidden漏洩検出 used_edge_ids のみ確認。 回答本文とhidden factsの意味的近さを検査する二段階validatorを追加する。
矛盾検出 同一subject + relation + 異なるobjectのみ。 time、polarity、confidence を含むclaim形式にする。
ledger永続化 to_dict() と from_dict() はあるが、ゲーム保存には未接続。 セーブデータへledgerを含める。
場所解放 used_edge_ids に依存。 回答本文や asserted_triples から場所参照を補助的に検出する。
