main.py
エントリーポイント

ゲームの起動口。新規ゲーム生成かセーブロードかをユーザーに選ばせ、Plotオブジェクトを構築してゲームループに渡す。

  • new_game() — ストーリー生成・保存、失敗時3回リトライ
  • load_game() — 過去のセーブから Plot を復元
  • main() — 起動メニューの表示と分岐
generate_story.py
ストーリー生成専用

ゲームループなしでストーリー生成のみを行う。生成後に main.py のオプション2でロードして遊ぶ運用を想定。

create_static_save.py
静的セーブ作成

LLMを使わずに手書きのストーリーで Plot オブジェクトを構築し、pickle保存する。開発・テスト時にLLM生成をスキップするために追加したファイル。

modules/llm_client.py
modules/

全LLM呼び出しの窓口。Ollama の OpenAI 互換エンドポイント（localhost:11434/v1）に接続し、リトライ処理を持つ。

  • llm(prompt) — 単発プロンプト（ストーリー生成用）
  • llm_messages(messages) — マルチターン（尋問用）
  • モデル: qwen2.5:7b
modules/story_init.py
modules/

ストーリー生成のオーケストレーター。各ステップを順番に呼び出してPlotオブジェクトを完成させる。

  • LLMにJSONでストーリー・容疑者設定を生成させ parse_story.py に渡す
  • write_timeline.py → shared_convo_gen.py → suspect_init.py の順で実行
  • 各ステップの結果を Plot オブジェクトに積み上げる
modules/parse_story.py
modules/

LLMが出力したJSONを Plot / Suspect / Victim / MurderDetails オブジェクトにパースする。

modules/write_timeline.py
modules/

LLMを使って15分間隔10タイムスタンプの行動タイムラインを生成し、Timestamp オブジェクトとして Plot に追加する。

modules/shared_convo_gen.py
modules/

タイムライン上で2人の容疑者が同じ場所にいるタイムスタンプに対し、LLMで会話内容を生成する。SharedInteraction として保存。

modules/suspect_init.py
modules/

各容疑者の一人称の記憶テキストファイルを生成する。タイムラインの各時刻の行動・会話をLLMに一人称で語らせ、ファイルに書き出す。

  • スライディングウィンドウ（直近2ターン）で文脈を維持しながら生成
  • 出力ファイルが後の RAG の入力になる
modules/assemble_suspect_context.py
modules/

容疑者の記憶生成プロンプト用に、ケース概要・自分のプロフィール・他の容疑者情報を組み立てたテキストを返す。

modules/make_save.py / load_save.py
modules/

story_elements/victim.py / murder_details.py
story_elements/

被害者情報と殺害詳細のデータクラス。pickle対応の __getstate__ / __setstate__ を持つ。

story_elements/timestamp.py / timeline.py / shared_interaction.py
story_elements/

タイムライン関連データクラス。各 Timestamp は「時刻」と「容疑者4人それぞれの行動」を保持する。SharedInteraction は同一時刻の2人の会話内容。

story_elements/pickle_plot.py
story_elements/

Plot オブジェクトを pickle でファイルに保存・復元する2関数のみのユーティリティ。

suspect_agents/suspect_agent.py
suspect_agents/

尋問を担うメインの LLM エージェント。RAG（ChromaDB）＋ LLM で各容疑者のキャラクターを演じる。

  • 初期化時: memory.txt → チャンク分割 → nomic-embed-text → ChromaDB
  • 質問時: 類似検索(k=4) → 記憶チャンク注入 → qwen2.5:7b で応答生成
  • 有罪/無実でシステムプロンプトを切り替え
suspect_agents/run_game.py
suspect_agents/

ゲームのメインループとUIを担う。容疑者の選択・尋問・犯人指摘の全インタラクションを管理する。

  • build_and_run_agents() — SuspectAgent × 4 を生成し事件概要を表示
  • choose_function() — 容疑者選択メニュー（1〜4 / switch / quit）
  • indict_suspect() — 犯人指摘と勝敗判定
LLM_functions/
LLM_functions/

LLMへのfunction calling用JSONスキーマ定義。LLMの出力形式を強制するために使われる。

  • set_up_story.py — ストーリー・容疑者4人の設定スキーマ
  • write_timestamp.py — タイムスタンプごとの行動スキーマ
  • shared_events.py — 共有イベントスキーマ
prompt_templates/
prompt_templates/

LLMに渡すプロンプトのテキストテンプレート集。ロジックから分離して管理されている。

  • story_init.py — 「著名な犯罪小説家」としてストーリーを作らせるプロンプト
  • generate_perspective.py — 容疑者視点の記憶テキストを生成させるプロンプト
  • shared_events.py — 2人の会話シーンを生成させるプロンプト
