Semantic Validator Implementation

作成日: 2026-06-23 | 対象: KG版 Murder Mystery | 目的: ルールベース検証 + LLM意味検証

1. 目的

Rule First
機械的に判定できるJSON形式、edge ID、triple形式はルールベースで即判定する。
Semantic Check
本文が秘匿情報を漏らす、公開事実や過去発言と矛盾する、事件を壊す重大な捏造をするケースをLLMで検査する。
Safe Fallback
全リトライ失敗時はraw出力を表示せず、安全な固定応答を返す。

2. 新しい検証フロー

GenerateLLM回答
→
Rule Validator形式とedge
→
Semantic Validator意味検証
→
Ledger保存
→
Display翻訳/表示

既存の validate_response() を第一防衛線として残し、その通過後に semantic_validate_response() を実行する。どちらかで失敗した場合は再生成する。 

is_valid, parsed, error = validate_response(...)
if is_valid:
    sem_ok, sem_result, sem_error = semantic_validate_response(...)
    if sem_ok:
        ledger.add_turn(...)
        return response

3. Rule Validator の強化

suspect_agents/validator_kg.py を強化し、JSON parse だけでなく、 used_edge_ids と asserted_triples の型と範囲を検査するようにした。

検査内容失敗例
JSON object LLM出力がJSONオブジェクトとしてparseできること。 自然文だけ、配列、壊れたJSON。
required fields response、used_edge_ids、asserted_triples を必須化。 used_edge_ids が欠落。
used_edge_ids type 配列で、各要素が文字列であること。 "used_edge_ids": "e1"
hidden edge leak used_edge_ids に hidden_edge_ids が含まれないこと。 Elenaが e14、e16、e17、e28 を使う。
visible edge subset used_edge_ids が、その容疑者の visible_edge_ids の部分集合であること。 存在しない e999 や、別容疑者専用edge。
asserted_triples type 配列で、各要素が長さ3の文字列配列であること。 ["Elena", "WAS_IN"]
ledger contradiction 同じsubject + relationで、過去と違うobjectを主張していないこと。 WAS_IN の場所が過去発言と衝突。

4. Semantic Validator

新規ファイル suspect_agents/semantic_validator.py を追加した。 現時点では modules.llm_client.llm() を使うため、対話生成と同じ qwen2.5:7b で動く。

LLMに渡す情報

入力目的
suspect_name 誰の回答を検査しているかを固定する。
question 探偵の質問。日本語モードでは英語化後の質問。
response_text 表示候補の英語回答本文。
visible_edges 回答が使ってよい事実。
hidden_edges 回答が明かしてはいけない秘匿事実。内部検証専用。
is_guilty 犯人の場合、hidden truthと矛盾する嘘は許可する。ただし秘匿事実の漏洩は許可しない。
ledger_text 過去発言との意味的矛盾を検査する。
asserted_triples LLM回答が自己申告した主張を補助情報として渡す。

期待する出力

{
  "verdict": "pass",
  "hidden_leak": false,
  "public_contradiction": false,
  "ledger_contradiction": false,
  "case_breaking_fabrication": false,
  "reason": "",
  "retry_hint": ""
}

Python側では verdict == "pass" かつ検査フラグがすべて false の場合だけ採用する。 fail と uncertain は再生成対象。

KGは人物の全行動を細かく保持していないため、自然な補足、感情、曖昧な記憶、会話上の言い換えは許可する。 case_breaking_fabrication は、新しい証拠・証人・アリバイ・犯行方法など、事件の論理を壊す重大な捏造だけを落とす。
semantic validatorにはhidden factsを渡すが、その出力は内部専用。UIには出さず、再生成用ヒントも具体的な秘密を含まない汎用文に丸める。

5. Retry と Fallback

rule validator または semantic validator が失敗した場合、最大 MAX_RETRIES = 3 回まで再生成する。 semantic validator のfail時は、秘匿情報を含まない安全なヒントだけを再生成プロンプトに付ける。 

[Previous output was invalid:
Regenerate the answer without revealing or implying any forbidden private information. Deflect if needed.]

すべて失敗した場合は、以前のようにraw出力を返さない。秘匿漏洩の可能性があるため、安全な固定応答にする。 

I need a moment to collect myself. Ask me again, Detective.

日本語モードでは、この固定応答も translate_response() を通して表示する。 また、質問開始時に last_used_edge_ids を空に戻すため、失敗時に前回のedgeで場所解放が誤作動しない。

6. 変更ファイル

  • suspect_agents/validator_kg.pyrule validatorを強化。必須フィールド、型、visible edge subset、hidden leak、triple形式、ledger矛盾を検査。
  • suspect_agents/semantic_validator.py新規追加。LLMでhidden leak、意味的矛盾、unsupported claimを検査。
  • suspect_agents/suspect_agent_kg.pyrule validator通過後にsemantic validatorを呼び、成功時だけledgerへ保存。safe fallbackも追加。
