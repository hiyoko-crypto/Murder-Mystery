2. アーキテクチャ：旧RAG vs 現行KG

項目旧RAG方式（suspect_agent.py）現行KG方式（suspect_agent_kg.py）
コンテキスト取得 質問をベクトル化→ChromaDB類似検索（k=4） KGサブグラフを全件プロンプトに渡す（検索なし）
埋め込みモデル nomic-embed-text（使用） 不要（現在未使用）
ターン間一貫性 なし（毎ターン異なるchunkが返るため矛盾が起きる） CommitmentLedgerが矛盾を検出・リジェクト
秘密情報の漏洩制御 検索次第で秘密chunkが出る可能性 hidden_edge_idsで明示的に禁止・Validatorで検証
質問依存性 質問の言い方でchunkが変わり回答が大きく変化 KGは固定。構造に基づいた安定した応答

3. 今回行った変更

  • modules/i18n.py NEW 言語切り替えモジュール。set_lang("en"|"ja") で起動時に言語を設定し、t("key") で全UI文字列を取得する。英語・日本語の全テキストを一元管理。
  • main_kg.py UPDATE ゲーム起動時に言語選択プロンプトを追加（1:English / 2:日本語）。選択結果を i18n.set_lang() に渡してからゲームを開始する。
  • suspect_agents/run_game_kg.py UPDATE 全print文・inputプロンプトをハードコードから t("key") 呼び出しに変更。英語・日本語どちらでも動作する。
  • modules/subgraph_to_prompt.py UPDATE LLMへのシステムプロンプトを言語対応化。日本語モード時は name_ja / bio_ja / tags_ja / interrogation_style_ja / speech_style_ja / detail_ja を優先使用。エッジトリプルのノード名・detailも日本語化。
  • modules/location_tracker.py UPDATE アイテム・場所の名前・説明・重要性を日本語モード時に _ja フィールド優先で返す _prop() ヘルパーを追加。
  • scenarios/the_final_act.json UPDATE 全15ノードに name_ja、キャラクター4名に bio_ja / tags_ja / interrogation_style_ja / speech_style_ja、11エッジに detail_ja、全場所に description_ja / significance_ja を追加。KGの英語構造は保持したまま日本語フィールドを共存させた。
  • modules/llm_client.py UPDATE 使用モデルを qwen2.5:7b に設定（qwen3.6:35b-a3bは生成速度の問題から一旦差し戻し）。

KGの言語設計方針（確定）

KGの構造（エッジID・関係名・ノードID）は英語で保持。
表示に使うテキスト（name / bio / detail / description）は _ja サフィックスで日本語版を共存。
別ファイルで管理せず、1つのJSONが唯一の真実（Single Source of Truth）。

現在判明している問題点

日本語応答の文体がまだ不自然になることがある
speech_style_jaフィールドを追加したが、qwen2.5:7bは7Bモデルのためロールプレイの精度に限界がある。 特に感情表現・人物らしい語り口を安定して出すには、より大きなモデルが効果的。
大型モデル（qwen3.6:35b-a3b）は生成が遅い
MacBook Pro（Metal GPU）での推論は23GBのウェイトをロードするため遅延が大きい。 品質 vs 速度のトレードオフとして現在は7bを使用中。
犯人正解時のメッセージがハードコード（英語）
「She entered Marcus's locked dressing room…」の正解詳細テキストが i18n 化済みだが、 解説文は現在のシナリオに依存した文言のため、シナリオ汎用化時に見直しが必要。
