1. 旧RAGアーキテクチャの問題点

問題 1 ― キャラクターの混同

LLM が会話ターンを重ねるうちに自分が誰かを見失う。実際に発生した例：

// Dr. Pemberton への質問に対する応答
"I spoke with Dr. Pemberton there..."
// → 自分自身を第三者として言及

根本原因：システムプロンプトにキャラクター名のアンカーがなく、長い履歴の中でアイデンティティが薄れる。

問題 2 ― 事実の捏造（ハルシネーション）

メモリファイルに存在しない行動をLLMが作り上げた例：

// メモリファイルの記述
"From about 9:30 to 10:30 I was in the billiard room..."

// 実際の応答
"By 10:30 PM, I had left to go back home."  ← 存在しない事実

根本原因：自由テキストチャンクは「参考情報」として渡されるため、LLMに厳守させる拘束力がない。

問題 3 ― チャンクの文脈欠落

文字数ベースで分割するため、関連する事実が別チャンクに切り離される。理由と行動が分断されたまま検索される。

問題 4 ― キャラクター間の情報漏洩

全容疑者の情報がシステムプロンプトに混在しており、知らないはずの情報をLLMが参照するリスクがある。

3. シナリオ設計の教訓

⚠️ 毒殺は推理ゲームとして成立しない

当初のシナリオは「毒を7:00PMに混入→9:15PMに死亡」という設計だったが、
実行時刻と死亡時刻のタイムラグにより以下の問題が発生した。 

// 毒殺の場合
実行時刻（7:00PM） ← Julian も Elena も部屋に入れた → アリバイが機能しない
死亡時刻（9:15PM） ← Julian はロビーにいた → この時刻のアリバイは意味がない

// 直接殺害の場合
実行時刻 = 死亡時刻（9:05PM）← Julian のロビーアリバイが完全に機能する ✅

結論：LLMでストーリーを自動生成する場合、実行時刻と死亡時刻に差が生じる凶器（毒・ガス・仕掛けトラップ）は生成禁止とすべき。

✅ 密室 + 直接殺害の組み合わせが論理的に明快

更新後のシナリオ「燭台による直接殺害」における推理チェーン：

1密室（内側から施錠、強制侵入なし）→ 侵入経路はシャフトのみ
↓
2換気口グレートが外れていた → 誰かがシャフトを使った
↓
3シャフト内でコンパクト発見（E.R.刻印）→ Elena Rostova の所有物
↓
4Julian のアリバイ（9:00-9:30PM ロビー、複数証人）→ 殺害時刻に現場不在 ✅
↓
5Leo はバックステージに入れない（パス没収）→ 物理的に不可能 ✅
↓
6Elena が犯人

4. 旧RAG vs 知識グラフ

観点旧（RAG）新（知識グラフ）
事実の拘束力 弱い 参考情報として渡すだけ 強い used_edge_ids で根拠を明示、Validator が検証
キャラクター分離 不完全 全容疑者情報が混在 厳密 サブグラフで知識を物理的に分離
犯人の隠蔽行動 なし 有罪フラグのみ 設計可能 hidden_edges を渡すことで緊張・回避を演出
一貫性の保証 なし ターンをまたいで矛盾が頻発 保証 Commitment Ledger で過去発言と照合
ハルシネーション 高リスク 存在しない事実を生成しやすい 低リスク グラフ外の事実を言わないよう制約
ChromaDB / Embedding 必要 ベクトルDB＋埋め込みモデル 不要 サブグラフがコンテキスト長内に収まる

6. 将来のシナリオ自動生成への制約

制約項目内容
凶器の種類 禁止 毒・ガス・仕掛けトラップ（実行時刻と死亡時刻がずれる）
推奨 鈍器・刃物・絞殺など直接的な物理攻撃
アリバイ構造 犯人以外の全容疑者が殺害時刻に複数証人付きのアリバイを持つこと
物的証拠 犯人だけが現場に残しうる物的証拠を1つ以上定義すること（イニシャル刻印など）
赤いニシン 無実の容疑者に強い動機を持たせるが、アリバイで完全否定できる構造にすること
