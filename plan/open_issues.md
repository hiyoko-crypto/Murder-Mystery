# 未解決の課題一覧

このセッションで発見・議論したが、まだ修正していない問題をまとめる。

## 1. フロントエンドの依存関係が未インストール

`frontend/package.json`・`package-lock.json`には`@xyflow/react`が記載されているが、`node_modules/@xyflow`が存在せず、Viteが`Failed to resolve import "@xyflow/react"`で起動時エラーになる。

- **原因**: 直近のコミット（`69867cf` feat: light theme overhaul, conversational indict flow, Case Notebook）で依存が追加された後、`npm install`が未実行と見られる。
- **対応**: `frontend/`で`npm install`を実行するだけで解決するはず。実行の承認待ち。

## 2. `used_edge_ids`の引用漏れ（本文で語った事実にエッジ引用が対応しない）

容疑者の応答テキストが場所・時刻などの事実を語っていても、JSON出力の`used_edge_ids`に対応するエッジIDが含まれないことがあり、`location_tracker.py`の証言による場所解放が発火しない。

- **再現方法**: Julian(`n_julian`)に対して開放的な質問（「敵はいたか」「他に知っていることは」等）を重ねると、ロビー在室（`e111`/`e112`）を語りながら引用しないケースが発生。修正前は10ターン中4回ミスマッチ。
- **一次対応済み**: Julianの`tags`から`"verbose"`、`interrogation_style`から`"Redirects suspicion toward Leo."`を削除し、無関係な質問への脱線・長文化を抑制 → ミスマッチは10ターン中1回まで減少、平均応答文字数も約34%減。
- **未対応**: 根本的な対処（`modules/subgraph_to_prompt.py`の出力フォーマット指示に「本文で言及した場所・時刻・人物には対応するエッジを必ず列挙する」旨を明記する）はまだ実施していない。キャラ設定の調整だけでは完全にはゼロにならない（修正後も1/10でミスマッチが残る）。

## 3. 逐語履歴（verbatim chat history）方式によるコンテキスト肥大化

`suspect_agents/suspect_agent_kg_verbatim.py`は過去のやり取りをそのまま`chat_history`に積み上げて毎ターン再送するため、ターンを重ねるごとにプロンプトの長さが線形に増える。

- **実測値**: Julianとの10ターン会話で`prompt_tokens`が2788→3910前後まで増加し、`NUM_CTX=4096`に接近。9ターン目でJSON生成が破綻（パースエラー）する再現が2回連続で確認された（キャラ設定修正の前後どちらでも発生）。
- **リスク**: 以前起訴評価で発生した「コンテキストオーバーフローで指示追従が崩れる」バグと同種の問題が、長時間の尋問プレイで再発する可能性がある。トリプル要約方式（最大直近6ターン、圧縮済み）よりコンテキスト消費が速い。
- **未対応**: 逐語履歴に最大ターン数の上限を設ける、または古いターンを要約・圧縮するなどの対策が必要。まだ着手していない。

## 4. `asserted_triples`フィールドが生成されるだけで使われていない

`suspect_agent_kg_verbatim.py`では記憶方式を逐語履歴に切り替えたため、LLMに`asserted_triples`を生成させて`validate_response()`で検証しているものの、その後どこにも読まれずに捨てられている。

- **影響**: プロンプト長・生成トークン数の無駄になっている（上記の課題3のコンテキスト肥大化にもわずかに寄与）。
- **未対応**: プロンプトから`asserted_triples`の指示・出力要求を削除するか、`validate_response()`の必須フィールドから外すかの判断がまだ済んでいない。

## 5. （優先度低・以前から保留中）ロケーション階層エッジの整理

`PART_OF`/`CONNECTS_AREA`/`HOSTED`/`FEATURED_PLAY`など、重複ではないが「低価値」と判断されたエッジ群（約9本）の削除検討。ユーザーの選択で明示的に保留中。
